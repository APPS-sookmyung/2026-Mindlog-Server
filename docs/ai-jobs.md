# AI 작업 저장·실행 계약

API 작업 UUID와 JobRunr 내부 UUID는 별개다. `ai_jobs`가 업무 상태의 원본이다. 요청 서비스는 계정→기록 순으로 잠근 트랜잭션에서 소유권·온보딩·버전·멱등성·쿼터 확인 후 `JobStore.submit`을 호출한다. 키 재요청 판정은 IdempotencyService가 담당한다. 임의 문자열 요청 키를 ai_jobs UUID로 강제 파싱하지 말고, 최초 실행에서 생성한 UUID를 저장한다.

DB 커밋 후 큐 등록 사이의 유실을 피하기 위해 PENDING 행을 발송 대기열로 사용한다. 30초 주기로 종류별 최대 100개를 가져와 JobRunr에 전달한다. 등록 실패나 프로세스 종료 뒤에도 재전송한다. 같은 작업이 여러 번 전달되어도 원자적 claim으로 한 시도만 실행한다. 처리 임대는 10분이며 클라이언트 호출 전체 제한 시간은 반드시 이보다 짧아야 한다. 임대가 끝나면 다른 실행이 복구하며 이전 시도의 결과는 시도 토큰 비교로 버린다.

`JobHandler`는 종류마다 하나만 등록한다. compute는 DB 트랜잭션 밖에서 외부 작업을 하고 apply는 완료 상태와 같은 트랜잭션에서 도메인 결과를 저장한다. `lockAndIsCurrent`는 계정→기록 잠금을 잡고 활성 소유자/data_generation/inputVersion/종류별 상태를 확인한다. 누락·탈퇴·초기화·수정된 입력은 false다. 준비 전과 반영 직전에 검사한다. reset은 같은 계정 잠금을 잡고 generation 증가/작업 삭제를 하나의 트랜잭션으로 처리해야 한다.

User/Before 실제 서비스가 아직 없어서 해당 도메인 어댑터는 연결 대기다. 운영용 가짜 검증기나 LLM은 등록하지 않는다. 연결되지 않은 종류는 실행하지 않는다. 이 PR만으로 실제 AI API 연동이 완료되지 않는다.

Before 반박과 일기 초안은 완료 시각+30분부터 폴링 시 만료로 처리해야 한다. 정리 작업은 본문만 제거한다. 성공 여부·입력 버전·generation·완료 시각은 최종 저장 검증용으로 유지한다. Before 성공 작업은 최종 Before 생성 시 입력 대조가 필요해 스냅샷도 TTL까지 유지한다. 나머지 작업과 실패 작업은 종료 시 입력을 즉시 지운다. 실패에는 안전한 이유 코드와 재시도 가능 여부만 저장하고 예외 메시지/프롬프트/제공자 응답은 기록하지 않는다.

V4는 기존 V1 수정 없이 시도 토큰·임대·재전송 시각을 추가한다. 런타임 시각은 주입한 Clock을 사용한다. 처리 중 영구 실패는 FAILED이며 사용자의 새로운 요청으로 재시도한다. 서버 중단에 따른 임대 복구만 자동 수행한다.
