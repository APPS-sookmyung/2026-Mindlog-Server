# 최종 기록 인사이트

이슈 #62, 스프린트 7 계획 #48. 최종 일기 저장 트랜잭션에서 등록한 RECORD_INSIGHT 작업만 처리한다. 상세 조회는 작업을 등록하거나 모델을 호출하지 않는다. 현재 범위는 record_comparison, situation_pattern, reflection_question 세 카드다.

수치 왜곡을 막기 위해 비교 문구와 과거 평균 문구는 서버가 계산한다. LLM에는 원문/최종 일기/Before/분석과 서버 집계값을 전달하고 1~1000자의 돌아볼 질문만 받는다. 이 길이는 구현상 제한이다. 실제보다 예상이 높았는지/낮았는지, 동점과 0점을 구분하며 평균은 소수 첫째 자리 HALF_UP으로 표시한다. 이전 기록이 없으면 없다고 안내한다.

과거 집계는 같은 사용자·같은 상황의 FINALIZED 기록 중 현재 기록을 제외하고 작업 등록 시각까지 완료된 기록만 사용한다. 다른 사용자의 기록, DRAFT, 다른 상황, 이후 완료한 기록은 제외한다. After 조회 전용 SQL에서 ERD의 Before를 조인하며 다른 도메인의 Repository 구현을 직접 호출하지 않는다.

최종 저장을 쿼터 실패로 되돌리지 않도록 내부 인사이트 작업은 실행 시작 트랜잭션에서 한도를 차감한다. 정상 중복 실행은 재차 차감하지 않으며 lease 만료 후 실제 재시도는 새 호출로 차감한다. 한도 초과는 안전한 RATE_LIMITED/retryable=true 작업 실패이고 이미 저장한 일기와 점수는 유지된다. 실패 작업을 임의 자동 재등록하지 않는다. 화면의 재시도 API는 명세 계약이 확정되는 후속 작업이며 이 워커 PR은 새 엔드포인트를 만들지 않는다.

완료 직전에 계정·소유권·generation·FINALIZED·inputVersion과 작업 시도 토큰을 재검증한다. 카드 저장과 COMPLETED는 같은 트랜잭션이며 결과가 오래되었거나 잘못되면 부분 저장하지 않는다. 기존 예약 유형의 인사이트는 삭제하지 않는다.

실제 계정/Before/LLM 연결 전에는 워커가 실행되지 않는다. 테스트 대체 클라이언트를 사용했고 실제 외부 호출은 하지 않았다. 기록 상세 리포트 응답과 실패 재시도 연결은 후속 리포트 범위다.
