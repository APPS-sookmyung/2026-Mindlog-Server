# 스프린트 7까지 구현·리뷰 안내

2026-09-30 기준. 모든 작업은 이슈 → 전용 브랜치 → 테스트 → main 대상 PR 순서로 진행했다. 리뷰 대기 중인 PR을 병합하지 않았다. 후속 브랜치에는 선행 변경이 누적되어 있으므로 아래 순서대로 리뷰하고, 병합 후에는 후속 PR을 최신 main 기준으로 정리한다.

PR #47에서 별도로 진행한 제약 매핑·소유권·페이징 브랜치까지 합쳤으며 이후 브랜치에는 모든 선행 변경이 들어 있다. 고유 기능만 먼저 살펴보려면 각 PR의 마지막 기능 커밋과 직전 선행 브랜치를 비교한다. main이 병합되지 않은 상태라 GitHub Files changed에는 누적 변경이 표시된다.

## 검증한 흐름

- Before를 참조하는 After DRAFT 생성, 원문/증상 수정, 목록·상세 조회
- 소유권·온보딩·현재 입력 버전·멱등 응답·쿼터 검증
- 분석 등록 → 처리 → 검증된 인용/태그/카드 저장 → 최신 결과 조회
- 일기 초안 등록 → 임시 생성·조회 → 30분 만료 → 사용자가 수정한 최종 일기 확정
- 최종 저장과 알림 해소·인사이트 작업 등록의 원자성
- 인사이트 한 번 저장, 같은 상황의 과거 완료 기록만 집계, 실제 0점 포함
- 중복 생성/분석/최종 저장, 같은 버전의 동시 수정, 수정과 최종 확정 경합
- 실패·늦은 결과·계정 generation 변경·탈퇴 후 결과 재생성 방지
- 정수 ID/버전/증상 ID의 소수·문자열·범위 초과 값 거부

테스트는 Testcontainers PostgreSQL 16과 테스트 전용 계정/Before/LLM 대체 구현을 사용한다. 로컬 개발 DB와 볼륨을 초기화하거나 삭제하지 않았다. 실제 LLM 호출은 하지 않았다.

최종 검증: `gradlew build` 성공. 282개 테스트, 실패 0·오류 0·건너뜀 0. 실행 가능한 Boot JAR도 빌드했다.

## 실제 연결을 기다리는 항목

1. **팀원 인증/User/Before 구현**: 실제 JWT 사용자 확인과 `AccountAccess`, `BeforeAccess` 어댑터. 계정 → Before/After → 작업 잠금 순서를 유지하고 초기화는 같은 트랜잭션에서 generation 증가와 데이터 삭제를 처리해야 한다. [계정 계약](account-access.md), [After 생성 계약](after-create.md), [작업 저장소](ai-jobs.md)를 참고한다.
2. **LLM 제공자·모델**: `LlmTransport` 실제 HTTP 구현, 제공자 키/모델 식별자/시간 제한, `LlmClient` 빈, 운영 쿼터 설정. 기본 쿼터 0이며 실제 연결 전 워커는 활성화되지 않는다. [LLM 계약](llm-client.md)을 참고한다.
3. **검토된 콘텐츠 시드**: 감정·상황·증상 3종만 확정 데이터를 넣었다. 왜곡 가이드·대처 문구·불안 패턴은 승인된 원문이 없어 비워 두었다. 왜곡 사전이 없으면 임의 태그를 생성하지 않고 일반 돌아보기 카드만 만든다.
4. **미결정 제품 범위**: 회복력 태그, 외부요인 Y/N, After 삭제 화면 등은 임의 추가하지 않았다. 인사이트 리포트 화면·실패 재시도 API와 주간 리포트/알림 확장은 후속 스프린트 범위다.

위 연결 전에는 서비스 전체를 운영 연동 완료로 판단하면 안 된다. 현재 PR은 독립 개발 가능한 로직·계약·테스트를 리뷰할 수 있는 상태다.
