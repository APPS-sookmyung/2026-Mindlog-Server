# 초기 데이터베이스 스키마

이슈 #20은 ERD의 28개 도메인 테이블과 제약 조건을 V1으로 생성합니다.
마스터 데이터의 실제 값은 다음 이슈에서 별도 마이그레이션으로 추가합니다.

## 실행과 기존 DB

PostgreSQL 16을 사용합니다. 애플리케이션 시작 시 Flyway가 먼저 마이그레이션하고
Hibernate는 `validate`로 매핑을 검증합니다. 적용된 V1은 수정하지 않고 V2 이후 파일로 변경합니다.
JobRunr의 내부 테이블은 라이브러리가 관리하며 V1에 복제하지 않습니다.
JobRunr 8.8.1의 SQL 저장소는 `@DependsOnDatabaseInitialization`으로 Flyway 적용 후 초기화됩니다.

기존 테이블이 있지만 Flyway 이력이 없는 DB는 자동 적용하지 않습니다.
`baseline-on-migrate=false`, `clean-disabled=true`를 유지합니다.
기존 개발 DB에 JobRunr 테이블 등이 있다면 먼저 백업하고 스키마와 이력을 검토해야 합니다.
지금 바로 확인하려면 기존 볼륨을 지우는 대신 별도의 빈 PostgreSQL DB를 만들고
`DB_URL`, `DB_USERNAME`, `DB_PASSWORD`로 연결합니다.
운영 DB 도입 시에도 기존 데이터 이관과 적용 절차를 별도로 검토합니다.

## 저장 규칙

- 시각은 `timestamptz`, 예정일·기간은 `date`, 알림 시각 설정은 `time`입니다.
  시각의 기본값은 DB에 두지 않습니다. 서비스가 주입받은 Clock으로 생성하고,
  API 응답의 Asia/Seoul 변환은 애플리케이션에서 처리합니다.
- 내부 숫자 ID는 `bigint GENERATED BY DEFAULT AS IDENTITY`입니다.
  API 작업 ID와 요청 키는 UUID이며 JobRunr 내부 ID와 별개입니다.
- 이메일은 최대 254자, 앞뒤 공백 없이 저장하며 `lower(email)`에 유일성을 적용합니다.
  닉네임·원문·일기는 `text`로 저장합니다. 인지 문자 수 제한은 VisibleLength로 검사합니다.
- 명세상 선택 값과 아직 생성되지 않은 AI 분석 결과는 NULL을 허용합니다.
  소유 FK, 상태·버전·분류, 마스터 표시 설정, 생성·수정 시각은 필수로 저장합니다.
  명시된 기본값 외에는 서비스가 값을 제공해야 합니다.
- After는 DRAFT일 때 점수·최종 일기·확정 시각이 모두 NULL이며,
  FINALIZED일 때는 모두 있어야 합니다. 상황은 연결된 Before를 통해 조회합니다.
- 분석 카드·인지왜곡 인용은 복수 저장할 수 있습니다. 동일 왜곡 유형의 여러 인용도 허용합니다.
- 외부 요인 응답은 복합 FK로 같은 After의 AI 인사이트만 참조합니다.
  인사이트의 external_factor 유형 여부는 서비스에서 검사합니다.
- 사용자별 리포트는 NULL 기간·상황에도 중복이 생기지 않도록
  PostgreSQL 16의 UNIQUE NULLS NOT DISTINCT를 사용합니다.
- AI 작업은 사용자·종류·요청 키가 유일합니다. After·작업 종류별 PENDING/PROCESSING은
  동시에 한 건만 존재할 수 있습니다. 완료·실패 이력은 다음 작업을 막지 않습니다.
- 소유권 일치, 활성 마스터 여부, 선택 개수, 입력 버전·세대 비교 및 상태 전이 권한은
  후속 서비스에서 검증합니다. FK만으로 다른 사용자의 참조가 차단되지는 않습니다.

## 삭제 정책

사용자 데이터는 사용자 삭제 시 CASCADE로 정리됩니다. Before와 After 삭제도 하위 분석·작업·알림으로
전파됩니다. 알림 삭제 시 전달 이력을 삭제합니다. 마스터는 참조 중이면 RESTRICT로 보호합니다.
기기 토큰 삭제 시 세션·전달 이력의 기기 참조만 SET NULL로 바뀝니다.

## 오류 매핑에 사용하는 고정 이름

| 제약 이름 | 의미 |
| --- | --- |
| ux_users_email_lower | 대소문자를 무시한 이메일 중복 |
| ux_after_logs_before_log_id | Before당 After 한 건 |
| ux_af_ai_feedbacks_after_log_id | After당 최신 분석 한 건 |
| ux_notifications_user_dedup | 종료된 알림도 포함한 중복 방지 |
| ux_ai_jobs_request | 사용자·작업 종류·요청 키 중복 |
| ux_ai_jobs_active_after_kind | 같은 After·작업 종류의 동시 실행 방지 |

이름을 변경하면 후속 ConstraintViolationMapper도 함께 변경해야 합니다.

## 검증

Docker Desktop을 실행한 뒤 `.\\gradlew.bat test`를 실행합니다.
기동 테스트와 스키마 통합 테스트는 Testcontainers의 별도 PostgreSQL 16을 사용하며
개발용 DB와 볼륨을 수정하지 않습니다. 최초 적용, 재적용, 비관리 DB 적용 차단,
이메일 중복, After 확정 조건, AI 작업 중복, NULL 리포트 중복, 복합 FK,
삭제 전파, 마스터 보호, 기기 참조 해제를 검증합니다.
