# 멱등 요청 처리

공통규약 8절에 따라 같은 사용자·데이터 세대·작업 범위·키의 성공 응답을 재생합니다.
같은 키에 다른 입력을 보내면 409 idempotency-conflict입니다.

## 호출 계약

1. 인증된 사용자 ID와 현재 data_generation으로 Scope를 만듭니다. 클라이언트가 보낸 사용자 ID·세대를 신뢰하지 않습니다.
2. operation에는 대상 경로 ID까지 포함하는 안정적인 서버 문자열을 사용합니다(예: after:77:finalize).
3. execute의 accessCheck에서 소유권·계정 상태·현재 세대를 확인하고 해당 도메인 서비스가 계정/기록 잠금을 획득합니다.
   이 검사는 재생 전에도 실행됩니다. 초기화·탈퇴도 같은 계정 잠금 규칙을 사용해야 합니다.
4. 상태 전이 조건과 inputVersion 검증은 action 안에서 수행합니다. 이미 성공한 같은 키의 재생을 확정 상태 검사로 막지 않습니다.
5. action은 같은 DataSource의 트랜잭션에서 변경하고 IdempotencyRecord를 반환합니다.
   원격 호출을 넣지 않습니다. AI는 내구성 있는 작업 등록으로 분리합니다.
6. 반환된 상태·본문·허용 헤더를 그대로 HTTP 응답에 사용합니다.

응답은 성공한 2xx만 저장합니다. 실패 시 예약 행과 도메인 변경이 함께 롤백됩니다.
실행 도중 프로세스가 종료돼도 미완료 예약이 커밋되지 않습니다.
동일 키의 동시 INSERT는 PostgreSQL UNIQUE에서 대기한 뒤 최초 커밋 결과를 읽습니다.
외부 트랜잭션에 참여하며 별도 REQUIRES_NEW 커밋을 하지 않습니다.

## 헤더와 입력

IdempotencyKeyFilter는 API 변경 요청에 전달된 헤더의 중복·형식을 검사해 요청 속성으로 전달합니다.
전체 API에 필수를 강제하지 않습니다. 대상 엔드포인트는 requireKey로 필수 여부를 적용합니다.
서버 제한은 공백 없는 ASCII 1~255자입니다. UUID 형태를 사용할 수 있지만 UUID만 강제하지는 않습니다.
이 제한은 공통규약에 구체 값이 없어 구현한 입력 제한이며 클라이언트 계약에 공유해야 합니다.

JSON 객체 키 순서·서식 공백은 정규화하고 배열 순서·문자열 공백은 보존합니다.
숫자는 BigInteger/BigDecimal로 읽어 서로 다른 정밀 값을 합치지 않습니다.
중복 속성 이름·뒤따르는 다른 JSON은 거부합니다. 요청 원문 대신 SHA-256 요약만 보관합니다.
응답 본문에는 기록 내용이 포함될 수 있으므로 사용자 데이터로 취급합니다.
헤더는 Content-Type, Location, Retry-After만 저장하며 인증 토큰·쿠키를 저장하지 않습니다.

## 마이그레이션과 삭제

V2 idempotency_records는 스캐폴딩의 IdempotencyRecord를 구현한 공통 인프라 테이블입니다.
V1 ERD에 빠져 있어 별도 추가했으며 기존 V1 파일은 변경하지 않았습니다.
탈퇴는 users FK CASCADE, 초기화는 계정 잠금을 획득한 같은 트랜잭션에서
deleteForUser 호출과 data_generation 증가를 함께 해야 합니다.
사용자·Before 구현은 팀원 영역이므로 실제 엔드포인트 연결은 해당 서비스에서 이 계약을 적용해야 합니다.
보관 기간의 근거가 없어 자동 만료로 동일 요청의 중복 생성을 허용하지 않습니다.

## 검증

PostgreSQL 16에서 동시 요청 단일 실행, 정확한 응답 재생, 다른 입력 충돌,
정밀 숫자·잘못된 JSON, 사용자·작업·세대 분리, 실패/외부 트랜잭션 롤백,
접근 검사 우선 수행, 초기화·탈퇴 정리를 검증합니다.
